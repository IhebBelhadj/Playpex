# Desktop server edition (`apps/server-desktop`) — Agent Guide

**Playpex Media Server** for Windows, macOS and Linux desktops (plan §8, step 6): Electron 44 used **only as a supervisor**, with no window. It runs the server core (`@playpex/server`) in an Electron `utilityProcess`, shows a tray icon, starts at login, restarts the server when it crashes, and updates itself. Everything else (settings, devices, logs…) is the server's web dashboard, opened in the user's browser. CommonJS, `const`/arrow functions (Electron's Node 24), no build step.

## Run / build
| Goal | Command |
|---|---|
| Development run | `npm run server:desktop` (repo root) = `electron .` here. Uses the real data dirs and port 28470 unless `PLAYPEX_CONFIG_DIR` / `PLAYPEX_CACHE_DIR` / `PLAYPEX_LOG_DIR` / `PLAYPEX_PORT` say otherwise. Prints `[tray] <icon>: <status line>` on each change (development only). Never registers itself for start at login. Server logs go to the terminal |
| Bundled ffmpeg | `npm run fetch-ffmpeg -w apps/server-desktop` (this machine) or `node build/fetch-ffmpeg.js --platform win32 --arch x64` / `--all` → `vendor/ffmpeg/<platform>-<arch>/` (git-ignored; downloads cached in `vendor/cache/`) |
| Installers | `npm run dist -w apps/server-desktop` (builds the dashboard with `npm run build --prefix ../dashboard`, fetches ffmpeg for this machine, writes the deb scripts, then electron-builder for this OS) → `dist/`. (`npm run build -w apps/dashboard --prefix ../..` from this folder fails under npm 12: "No workspaces found".) `dist:linux` (AppImage + deb), `dist:win` (NSIS; cross-builds from Linux, unsigned, fetches the Windows ffmpeg), `dist:mac` (dmg + zip, needs a Mac), `pack` (unpacked only). `--publish never` unless releasing |
| Icons | `npm run icons -w apps/server-desktop` (needs `rsvg-convert` + ImageMagick `magick`) after changing the Playpex mark; results are committed |

Testing without touching your own setup: point `PLAYPEX_*_DIR` at temp dirs, set another `PLAYPEX_PORT`, `XDG_CONFIG_HOME` (Linux autostart entry) and put a fake `xdg-open` first on the `PATH` (it's how the dashboard opens). Set `APPIMAGELAUNCHER_DISABLE=1` when running the AppImage on a machine with AppImageLauncher (else it shows an "integrate?" dialog). Stop with SIGINT (graceful).

## How it talks to the server
The server is the unchanged headless entry; when `process.parentPort` exists, `apps/server/lib/host.js` links it to us (message list at the top of that file). The dashboard reaches the supervisor through the server: `GET|PUT /api/v1/admin/host`, `POST /admin/host/update/check|install` → `host.request()` → `{type:'request'}` here → reply. The tray reaches the server the other way (`server.request('pairing.approve', {code})`…). The status for the tray arrives every 5 s and right after pairing / device / session events.

## Gotchas
- **No windows**: `window-all-closed` is handled so nothing quits; dialogs (`dialog.showMessageBox`) and notifications work without a window.
- **Graceful stop matters**: the server destroys its torrent engines and closes SQLite; `before-quit` waits for `server.stop()`. Killing the main process with SIGKILL leaves the child to the OS.
- The packaged app reads nothing from the repo: dashboard from the asar (`@playpex/server/public`, build it before packaging), migrations from the asar, ffmpeg from `resources/ffmpeg`. `npm run dist` builds the dashboard first.
- Unsigned builds: Windows SmartScreen warns, macOS Gatekeeper blocks (signing is §14.4). Auto-update needs published GitHub releases (none yet: the updater reports "No published versions on GitHub").
- Linux GNOME needs the AppIndicator extension for the tray icon.
- Until plan step 9 the TV app embeds its own server: whichever starts first holds port 28470 (the desktop app then shows "Another Playpex server is running").
