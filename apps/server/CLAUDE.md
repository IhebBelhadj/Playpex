# Streaming Server (`apps/server`) — Agent Guide

Playpex Media Server core: Node/Express (CommonJS, ES5-style `var`/callbacks/promises) that the Angular UI talks to. Being split out of the TV app (`docs/server-separation-plan.md`, steps 0–6, 8 and 10 done; 7, the headless packages, deferred). What clients may rely on is written for client authors in `docs/api/`. Nothing listens on `require`: hosts call `start()` / `stop()` from `index.js`.
- **Headless**: `npm run server` from the repo root (= `node apps/server/bin/playpex-server.js`; `… set-port <n>` saves another port; `… admin set <username>` and `… devices list|pending|approve <code>|deny <code>|revoke <id>` manage auth, see **Auth**). Logs uncaught exceptions and exits 1; SIGINT/SIGTERM stop gracefully. Port held by another program → **recovery mode** (below); `--no-recovery` exits 1 instead (Docker, scripts).
- **Desktop** (plan step 6): `apps/server-desktop` runs `bin/playpex-server.js` unchanged in an Electron `utilityProcess`; `lib/host.js` then links it to the supervisor over `process.parentPort` (tray status, stop, pairing approvals, pause all; the dashboard's desktop settings and updates the other way). Bundled ffmpeg arrives through `PLAYPEX_FFMPEG_DIR`.
- **Dashboard**: `apps/dashboard` builds into `public/` (git-ignored), served at `/` (see `apps/dashboard/CLAUDE.md`).
- **Embedded** (until plan step 9): `apps/tv/electron/main.js` calls `start()` inside the Electron main process (Electron 44 → Node 24), so an uncaught exception here crashes the whole app. If the port is taken by a Playpex server (`GET /api/v1/server` answers), the TV app uses that one; if by something else, it starts ours on a free loopback port.

The torrent part started from `peerflix-server`'s structure (a standalone copy lives in the author's Playpex-backend repo, linked in the root README); since media-server plan step 1 it is a torrent client behind an engine port (`lib/torrents/`, see **Downloads and the torrent engine**). Dependencies are declared in **`apps/server/package.json`** (npm workspace `@playpex/server`; installed from the repo root).

| `index.js` | Core entry: `start(options) → {port, host, urls, id, name, …}` / `stop()`, `info()`, plus `settings` and `logger`. Sets `dns.setDefaultResultOrder('ipv4first')` first (DHT/UDP trackers are IPv4-only; without it the DHT never bootstraps on IPv6/NAT64 networks), loads the repo root's `.env` if present. `start()`: settings → logger → `server.json` id → `lib/torrents/client.init` (not in recovery mode; option `torrents` overrides its options for a run: tests use `{engine: 'fake', discovery: false}`) → listen on `general.port` (**fixed, default 28470; no sliding**) at `127.0.0.1`, or `0.0.0.0` with `network.lanSharing`. Then starts the library's scanner (`lib/library`, not in recovery mode; option `library`: `false` = off, else its start options), LAN discovery (`lib/discovery.js`, only when listening on the LAN; option `discoveryPort` for tests), the DLNA server (`lib/dlna`, only with `dlna.enabled` and on the LAN; option `dlna: {port, ssdpPort, lan}` for tests), attaches the events WebSocket (`lib/events.js`), starts `lib/system.js`'s sampler and warms up `lib/auth` (logs a hint while the admin has no password). `stop()`: waits for the running library scan to stop, stops DLNA (ssdp:byebye), sends the mDNS goodbye, closes the torrent client (progress saved, engine stopped, data stays), closes the events socket and HTTP (drops open streams), drops the auth instance and closes the DB. **`startOrRecover(options)`**: `start()`, but when another program holds the port (and it isn't a Playpex server: `err.playpex`, rejected) starts in **recovery mode** (`start({recovery: {reason, port, owner, message}})`: `127.0.0.1:0`, `info.recovery`, client routes answer 503 `BUSY`, only `/server`, `/admin/*`, `/auth/*`, events and the dashboard work). **`restart()`**: `stop()` + `startOrRecover(last options)` (the dashboard's Restart: port, LAN sharing, download dir; the torrent client re-reads the download dir and the engine on every start). |

## HTTP API (`lib/api.js`)

**Every route lives under `/api/v1`** (a `v1` router in `lib/api.js`); the paths in the tables below are relative to it (`GET /torrents` = `GET /api/v1/torrents`). The contract is **`packages/protocol/openapi.yaml`**: change a route or an answer there first, regenerate the types (`npm run generate -w packages/protocol`), and run the contract test (`npm test -w apps/server`; `PLAYPEX_TEST_NETWORK=1` adds the provider routes). Unversioned paths from before (`/torrents/…`, `/upload`, `/youtube/…`, `/api/<x>`) are rewritten onto v1 by `legacyAliases` until plan step 9.

- **Errors**: always `{ error, code }` through `lib/errors.js#fail(res, code, message, extra?)`; codes and statuses in `@playpex/protocol` `ERROR_CODES` (`INVALID` 400, `DEVICE_REQUIRED` 400 (settings routes without a device id), `PAIRING_REQUIRED` / `ADMIN_REQUIRED` 401, `FORBIDDEN`, `NOT_FOUND`, `CONFLICT`, `TOO_MANY_ATTEMPTS`, `INTERNAL`, `UPSTREAM` 502, `PROBE_FAILED`, `PROVIDER_NOT_CONFIGURED` 503, `TRANSCODER_UNAVAILABLE` 503, `BUSY` 503 (a limit), + `HOST_NOT_ALLOWED` / `ORIGIN_NOT_ALLOWED` 403, `CLIENT_TOO_OLD` / `SERVER_TOO_OLD` 426, `NOT_SUPPORTED` 501 (desktop-only routes on another host)). Some list routes keep an empty list next to it (`torrents: []`, `subtitles: []`). Unknown routes → 404 `NOT_FOUND`, malformed JSON → 400 `INVALID`. Actions without data answer `{ ok: true }`.
- **Versions**: optional `X-Playpex-Client: <name>/<version>; api=<n>` → 426 when outside `MIN_API_VERSION`…`API_VERSION`.
- **Docs**: `GET /openapi.yaml` (the spec, from `@playpex/protocol`; no auth, also in the desktop package) and `GET /docs` → 302 `/docs` (the dashboard renders the client author guide `docs/api/` there, public). **A protocol change updates the spec, then the guide** (`docs/api/*.md`: flows, limits, error codes, event topics).
- **Auth**: every route but `GET /server`, `/openapi.yaml`, `/docs`, the device flow and `/admin/setup` needs a paired device's token, a local (loopback) client, or the admin; see **Auth** below. Never log tokens: `requestLog` drops query strings (`?access_token=`), and ffmpeg's stderr is redacted (`internal=`).

### Auth (`lib/auth/`, plan §6.3)
One Better Auth user, the **owner** (admin), made without a password on first start. Devices pair with the **RFC 8628 device flow**; their token is a Better Auth session of the owner plus a `devices` row (made by a `databaseHooks.session.create.after` on `/device/token`). No `bearer` plugin: our `identify` checks tokens itself, so device tokens authenticate nothing of Better Auth's.

### Torrents
Device = a paired device's own id (its token); for local clients the `X-Playpex-Device` header or `?device=` (media URLs), else the client's address. Every route below that names a device takes or refreshes its **lease** (`lib/sessions.js`).
| Method & path | Behavior |
|---|---|
| `GET /torrents` | The **running** torrents, serialized (`GET /downloads` lists every one). |
| `POST /torrents?device=` body `{link}` | Magnet, http(s) .torrent URL, or bare 32/40-char hash (never a local path). Returns `{infoHash}` (lowercase). A download with intent `stream`; a known hash is reused (paused → runs again, completed → plays from disk, nothing starts); acquires the device's lease. Starting one past `streaming.maxTorrents` running torrents → `sessions.canAdd` makes room (unheld streams stop, then a download nobody watches goes back to the queue) else 503 `BUSY`. |
| `POST /upload` (multipart `file`) | The same from an uploaded .torrent (read by the route, unlinked after). |
| `POST /torrents/:infoHash/keepalive?device=` body `{positionS?, durationS?, paused?, title?, profileId?, file?, media?}` | Refreshes the lease; the body (all optional) is what the session shows; `media` `{mediaType, tmdbId, season?, episode?}` (+ `title`) and `profileId` are kept with the download (`title_ref`). The TV player sends it every 60 s. |
| `GET /sessions` (admin) | One entry per lease: `{id, deviceId, deviceName, paired, client, address, infoHash, torrentName, file, method (direct\|audio-transcode), streaming, since, lastActivity, playback (last keepalive), torrent: {peers, downloadSpeed, uploadSpeed, downloaded, length}}`. For the dashboard's Activity (step 5). |
| `DELETE /sessions/:id` (admin) | Closes the session's open streams and releases its lease. |
| `GET /torrents/:infoHash` | Any download the server keeps (404 = unknown / removed); **only `{infoHash}` until metadata arrives** (the UI polls). |
| `POST /torrents/:infoHash/start/:index?` / `stop/:index?`, `POST …/deselect` | Select/deselect files by index (→ `torrents.select` by path; `deselect` was a `GET` before step 1). |
| `POST /torrents/:infoHash/pause` / `resume` | Pause (state `paused`, persisted) / run again with its intent (stream: admission, 503 `BUSY`). |
| `DELETE /torrents/:infoHash?device=` | **Releases the device's lease** (`{ok: true}` even if it had none). **Never deletes**: 30 s after the last lease, a `stream` download pauses (`completed` if its files are done), a `download` keeps running; "remove when watched" (player ≥ 90 %) deletes it. |
| `GET /torrents/:infoHash/stats` | `metadata` (bool), `peers`, `speed`, `traffic` (the engine's counters since the torrent started), `eta`, `paused` (not running), `state`. Zeros while stopped; the player polls it while loading/buffering. |
| `GET\|HEAD /torrents/:infoHash/files/:path?device=` (+ `probe/`, `keyframe/`, `transcode/`) | **Aliases of `/media/{ref}`** (below), same handlers (`lib/routes/media.js`). The streaming endpoint: Acquires the lease (the session's `file`, method `direct`; an open response keeps it from being reaped). GET: `torrents.prepareStream` (a finished file of a stopped download is read **from disk**, no engine; else the torrent runs again (admission → 503 `BUSY`) and a `stream` download selects only this file, a `download` adds it), `prefetchTail` (last 2 MB, MKV index), `Range` → `206` + `pump(torrents.stream(…), res)`. HEAD answers from the metadata without starting anything. Socket timeout 1 h. |

## User data (profiles, watchlist, resume, recommendations)

Three layers; each only imports the one below it:

```
lib/services/   business rules, validation, ServiceError {code, status}   ← routes call these
     │ repositories only (contract: lib/data/contracts.js)
lib/data/       data access layer: createRepositories(db) → {profiles, watchlist, progress, history, ratings, settings, downloads}
     │          current implementation: lib/data/drizzle/*.js
lib/db/         schema.js (Drizzle tables) · driver.js (node:sqlite ↔ Drizzle) · index.js (open + migrate) · migrations/
```

- `index.js` loads the repo root's `.env` (dotenv) if present; API keys are read through `lib/settings.js` (`providers.tmdbApiKey` ← `TMDB_API_KEY`, …), so `settings.json` works too.
- **Database**: SQLite file `<config>/playpex.db` (Linux `~/.config/Playpex/playpex.db`), Node's built-in `node:sqlite` (no native module) through Drizzle's `sqlite-proxy` adapter (Drizzle 0.45 has no node:sqlite driver). Opened lazily by `lib/userData.js` (`userData.services()` → Promise of the services), migrations applied on open.
- **Schema change**: edit `lib/db/schema.js`, run `npm run db:generate` (drizzle-kit, config in `apps/server/drizzle.config.js`; works from the root too), commit the new file in `lib/db/migrations/`. Never edit an applied migration.
- **Replacing the database**: another SQLite driver (better-sqlite3, libsql) → only `driver.js`. Another engine → new schema/driver in `lib/db` and a repository implementation satisfying `contracts.js`, selected in `lib/data/index.js`. Repositories return plain objects, `null` for not found, and reject with `data/errors.DuplicateError` on unique violations; they use array results + `util.first` instead of SQLite-only `.get()`.
- **Don't use `db.transaction()`**: with the async proxy over a sync driver, other requests can run between BEGIN and COMMIT. Use `db.batch([...])`, which the driver runs in one BEGIN/COMMIT without yielding.
- **Services** (`createServices(repositories, {catalog, now, publish})`; `publish` = `events.publish`, given by `lib/userData.js`):
  - `profiles`: list/get/create/update/remove, optional 4–6 digit PIN (scrypt; `setPin`, `unlock` with 5-failure / 30 s lockout), `lastUsed`. Max 8 profiles, names unique case-insensitively. Public shape has `hasPin`, never the hash. Removing a profile cascades to all its rows. The PIN only gates the UI; the DB is not encrypted.
  - `watchlist`: list/contains/add/remove/toggle.
  - `playback`: `saveProgress` (finished at ≥ 90 %, first finish appends to history), `getResume` (null under 5 % or finished; includes `infoHash`/`filePath` of the release), `continueWatching` (`kind: 'resume'|'next'` — for `'next'` the UI resolves the following episode), `titleProgress`, `markWatched`/`markUnwatched`, `history`.

  - `downloads`: `list`, `get`, `create` (defaults filled; the existing row for a known hash), `update`, `remove`; checks hash / state / intent. Written only by `lib/torrents/client.js`.
  - `library`: `folders`, `folder`, `addFolder({path (absolute; pass its realpath), kind, audience?, dlna?, builtin?})` (409 for a known path; `lib/library#addFolder` checks the disk and overlaps first), `updateFolder`, `removeFolder` (its files' rows too, nothing on disk; 409 for the builtin one), `files(folderId)`, `file(id)`, `addFile(folderId, {relPath, size, mtime?, state?, parse?, probe?, subtitles?})` (`relPath` relative, `/`-separated, no `.` / `..` / empty parts / backslashes: 400), `updateFile`, `removeFile`, `queryFiles({folderId, state, itemId, q, limit ≤ 500, offset})` (with each file's item), `filesFor(identity)` (a movie's / an episode's files in state ok, for the play pipeline), `counts()` (per folder and state), `item(id)`, `match(fileId, identity, details, matchedBy)` (finds or makes the item: one per movie / per show + season + episode; a stronger decision is kept: admin > nfo > auto), `unmatch`, `ignore(fileId, bool)`, `purge()` (rows missing for 7 days, then items nothing uses). Written by `lib/library` and the admin routes; `lib/media` reads it.

## Downloads and the torrent engine

Plan: `docs/media-server-plan.md` §4 (step 1 done; 1b, rqbit, next). **Every torrent is a download**: a row of `downloads` (migration `0005_downloads`; `lib/data/drizzle/downloads.js` → `services.downloads`, which only keeps rows valid: the client is the only writer) + its metainfo in `<config>/torrents/<hash>.torrent`. With both, any engine can take the torrent again: an engine's own state is a cache.

```
routes · sessions.js · storage.js · system.js · host.js        (info hashes, file paths, our states)
                    │
             lib/torrents/client.js   ← states, intents, queue, seeding rules, DB, events
                    │  engine port (lib/torrents/port.js), through the registry only
      ┌─────────────┴──────────────┐
engines/torrent-stream.js     engines/fake.js (tests)          (rqbit: plan step 1b, one more adapter)
```

- **States**: `queued` · `downloading` · `seeding` · `checking` (running = "active"; `checking` = the engine verifies data on disk, torrent-stream on every start) · `paused` · `completed` (every selected file done) · `error`. **Intents**: `stream` (a player; pauses when the last lease goes) / `download` (runs to the end without clients; the admin's Start, `POST /downloads`).
- **Lifecycle**: add (stream) → `downloading` (largest file selected until the player streams one) → leases gone + 30 s → `paused` (or `completed`); Start → intent `download`, `queued` → `downloading` → done → `seeding` until `downloads.seedRatio` (uploaded / size) or `seedMinutes` (either; both 0 = no seeding) → `completed`. Pausing destroys nothing: `deactivate` sets the state first (in memory, so limits count at once), then the engine pauses (or, without the `pause` capability, stops and is re-added later).
- **Limits**: `downloads.maxActive` downloads run at once (FIFO by `addedAt`, `pump()`); all running torrents stay under `streaming.maxTorrents`; a stream that needs a slot asks `sessions.canAdd` (admission). `downloads.paused` ("pause all", the tray, kept in settings.json): running downloads go back to `queued`, nothing is pumped; streams still play.
- **Streaming**: `prepareStream(hash, path)` → `'disk'` for a finished file of a stopped download (read with `fs`, no engine; part of plan §5.4 done early), else the torrent runs; `stream(hash, path, range)` → a `Readable` (the engine waits until it is ready / checked); `prefetchTail` once per file per run.
- **Start / stop of the server**: `init()` opens the DB (without one: in memory only, logged), starts `downloads.engine` (fails → the default `torrent-stream`, reason in the Overview), loads rows + metainfo, **imports `torrents.json` once** (hashes whose torrent-stream cache `<cache>/torrent-stream/<hash>.torrent` and data exist become `paused` streams; the file is renamed `torrents.json.imported`), reconciles (torrents the engine has and we don't: stopped, data kept; running downloads → `queued`, running streams → `paused`/`completed`), polls stats every 2 s (progress, ratio, state from the engine; rows saved every 30 s and on every state change). `close()` saves progress and stops the engine. Never rejects: no engine → adding / streaming answer 503.
- **Events**: `download.added` / `download.updated` / `download.removed` (everyone); `torrent.stats` stays (leased torrents).
- **Engines** (`downloads.engine`, restart): `torrent-stream` (built in, default: fast start and seeks; re-checks data on every resume), `rqbit` (fast resume, real pause, uTP; **8–38 s seeks** on a busy download: for downloads), `torrentd` (our Go sidecar on anacrolix/torrent, recommended for streaming: starts as fast as torrent-stream, seeks in ~2 s, fast resume, real pause, live speed limits; its dial settings are tuned in `engines/torrentd/main.go`, see the plan's §4.7). The sidecars are optional downloads (Settings › Downloads › Install, `npm run install:engine -- <id>`, `npm run build:torrentd`); a chosen engine that can't start → torrent-stream, the reason in Overview `downloads.engineError`. Switching: each download is added to the new engine from our row + metainfo (paused unless running); data stays where it is; an engine with its own session (rqbit) gets our selection again and is paused at reconcile.
- **Sidecar specifics** (in their folders only): rqbit has no paused add (kept in the adapter until start), needs `--fastresume`, writes a one-file folder torrent without its folder (so `output_folder` is explicit and magnets are listed with `list_only` first), counts whole pieces in `total_bytes`; its web UI stays on behind the password. torrentd's API mirrors the port (see `engines/torrentd/main.go`), prints `LISTENING <addr> PEERPORT <n>`, stops when its stdin closes; `GET /debug/status` = anacrolix's status page. Their rate limiters need a burst > 0 (an unlimited limiter with burst 0 blocks every connection).

**The engine port** (`lib/torrents/port.js`, version 1): `init({dataDir, stateDir, peerPort, discovery, limits, log})`, `close`, `health`, `add({infoHash, magnet?, torrentFile?, savePath, files?, paused?, trackers?, peers?})` (idempotent), `metadata(hash)` (`{name, length, pieceLength, files: [{path, size, offset}], torrentFile}`), `start` / `pause` / `stop` (forget, data kept) / `remove(hash, {deleteData})`, `select(hash, paths | null)`, `stats()` (one `Map` for all: `state, metadata, doneBytes, sizeBytes, downBps, upBps, peers, peersUnchoked, seeds, downloadedBytes, uploadedBytes, checking, pieces`), `stream(hash, path, {start, end})` → `Promise<Readable>`, `setLimits`, `list`, events `metadata` / `done` / `error`. Every method answers a Promise and rejects with an `EngineError`. **Capabilities** (`fastResume`, `pause`, `rateLimits`, `fileSelection`, `streamPriority`, `persistentSession`) decide the client's behaviour, never the engine's id. torrent-stream: `pause` true (it destroys the torrent's engine), `fastResume` false. **Rules**: only `client.js` uses an engine, only through `engines/index.js`; no engine object, id, error or option crosses the port (`npm run check:engines`); a new engine = one adapter + passing `test/engines.test.js`.

## Lifecycle of a torrent

```
POST /torrents {link} ?device=A
  └─ torrents.add(link, {intent: 'stream'})       known hash → reused (paused: runs again; completed: nothing starts)
       → admission (sessions.canAdd: 503 BUSY past maxTorrents) → downloads row → engine.add (+ lib/trackers.js)
       ├─ sessions.acquire(hash, A)                lease {deviceId, lastActivity, open streams}
       └─ engine 'metadata' → <config>/torrents/<hash>.torrent, largest file selected → GET /torrents/:hash lists files
GET /torrents/:hash/files/:path?device=A (Range) → lease refreshed, stream tracked → prepareStream
       (disk if finished, else running + only this file selected) + tail prefetch → pump(torrents.stream(range))
POST /torrents/:hash/keepalive?device=A   every 60 s from the player (a paused video makes no requests)
DELETE /torrents/:hash?device=A → A's lease released
  └─ no lease left → after 30 s (unless a device acquires it again):
       torrents.released(hash, {watched}) → stream: paused / completed (data kept); download: keeps running;
       "remove when watched" + the player reached 90 % → removed with its data
reaper (every 60 s): leases without an open stream and idle > streaming.idleTimeoutMinutes → released
```

Two clients on one torrent each hold a lease, so one leaving doesn't cut the other off. A client that crashes is cleaned up by the reaper (≤ idle timeout + 1 min + 30 s). ffprobe / ffmpeg read a file still downloading through `/media/{ref}` as the requesting device (`?device=…&internal=<per-process secret>`: lets them in without a token, and their reads keep the lease without changing the session's method); a finished file of a stopped download, and any library file, from its path (`lib/media#input`). Transcodes: at most `streaming.maxTranscodes` at once; a new one from the same device and file replaces the previous (the player restarts the stream on every seek), else 503 `BUSY`.

## Gotchas
- **Trailers**: YouTube enforces proof-of-origin. Every approach tested in Oct 2026 stops at ~1 MB (403): `youtubei.js` clients (iOS works only for the first chunk), PO tokens minted with `bgutils-js` in jsdom and in a real hidden Chromium window, and SABR via `googlevideo` ("attestation required"). `ytdl-core` and `@distube/ytdl-core` are dead. Realistic fix: official IFrame player in the UI.
- **Swarm reality**: provider seed counts are often stale; streams can sit at 0 kB/s with few peers. An MKV whose index sits at the end used to take ~55 s to start on a slow swarm; `prefetchTail` addresses that.
- Chromium can't decode Dolby/DTS audio: `lib/transcode.js` + `GET /media/:ref/probe` (ffprobe: `{duration, video, width, height, hdr, audio, subtitles, transcode}`) and `GET /media/:ref/transcode?t=&audio=` (ffmpeg: video copied, audio → AAC stereo, live Matroska — fMP4 lost the audio/video gap after `-ss` and drifted by seconds; not byte-seekable, so every seek restarts it at `t` = the keyframe from `GET /media/:ref/keyframe?t=` with `-noaccurate_seek`, so video and audio start together). Binaries resolved by `lib/ffmpeg.js`; the desktop installers bundle a pinned LGPL build (`apps/server-desktop/build/ffmpeg.json`), headless installs don't (step 7, deferred to the plan's §13).
- `torrent-stream`, `read-torrent` are old but working; torrent-stream re-checks a torrent's data every time it starts (state `checking`: a big file takes a while before it streams again). The rqbit adapter (plan step 1b) fixes that. Engine errors that don't stop a torrent (torrent-stream's cache writes) only set the download's `error` text.
- No unversioned routes any more (the `/torrents`, `/api/…` aliases of the all-in-one app went with plan step 9): everything is `/api/v1`.
- CORS trusts only the server's own origin, `ng serve`'s (`http://localhost:4200`) and `network.corsOrigins`. The TV app (file://) sends no `Origin` (its shell strips it, `apps/tv/electron/auth.js`); `null` / `file://` are refused for state-changing requests (contract test "no unversioned routes, no Origin: null").
