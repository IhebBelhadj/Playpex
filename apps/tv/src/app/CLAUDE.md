# Angular UI (`apps/tv/src/app`) — Agent Guide

Single NgModule app (`app.module.ts`), Angular 14, no lazy loading, no standalone components. Everything is driven by keyboard via spatial navigation and coordinated through RxJS Subjects in root services. See the root [`CLAUDE.md`](../../CLAUDE.md) for the overall architecture, data sources and ports.

## Layout of the shell (`app.component.html`)

```
<splash>                         full-screen intro video; emits 'clearSplash' when done
.masterContainer (flex row)
  <menu>                         left nav, full height: logo (+ room for <back-button>) on top; Search / Movies / Tv shows / Watch list / 18+ (not for kids) / Settings centered (the screens declared with a menu entry); the server in use (→ /connect) and the current profile (→ /profiles) at the bottom
  <notification-handler>         error popup (px-dialog, alert level) with an OK option
  <torrent-picker>               modal "Choose a torrent" list shown before playback (px-dialog)
  <px-dialog-host>               the Dialogs service's dialogs (ui/overlay), e.g. "Resume / Play from the beginning"
  <connection-lost>              modal "Lost connection to <server>": Retry / Choose server (ConnectionService; px-dialog, system level)
  <router-outlet>                pages (see routes)
  <back-button>                  mouse-only round "Back" button, top left under the logo (see BackButtonComponent)
  <clock>                        top-right clock
.overlay
img.newBackground / img.previousBackground   full-screen backdrop crossfade (driven by BackgroundService)
```

## Two sections, one set of components

Movies and TV shows share the home page, slider and description panel. The route's `data.media` (`'movie' | 'tv'`) picks a **`Catalog`** (`catalog.ts`) from `MoviesService.catalogs`:

| | `catalogs.movie` | `catalogs.tv` |
|---|---|---|
| Rows | `categories` in `categories.ts` | `showCategories` in `categories.ts` (all `discover/tv`; trending/popular endpoints ignore the language filter) |
| List URL | `/movies/list` | `/shows/list` |
| Detail URL | `/movies/movie/:id` → `MovieOptionsComponent` | `/shows/show/:id` → `ShowOptionsComponent` |
| Enrichment on focus | TMDB details + YTS torrents/rating/runtime | TMDB TV details (genres, seasons, imdb id) + IMDb rating (`ImdbService.title`) |

A `Catalog` holds `items` (BehaviorSubject `{[category]: item[]}`, created in category order), `reachedPages`, and the page-request / selection channels (the slider position is the movement system's `PositionStore`, `catalog:<media>`). It lives in the root service so it survives trips to the player. `MoviesService.catalogForUrl(url)` maps a list URL back to its catalog (used by `AppComponent`).

TV items carry `media_type: 'tv'`; `<movie-description>` uses that to show `name`, `first_air_date`, season count and TMDB score instead of the movie fields.

|---|---|---|
| `/` | redirect → `/profiles` | |
| `/display` | `DisplaySetupComponent` (`display-setup/`) | First start on this device: "How big should Playpex look?" (`DisplayGuard`, requirement `display` on `/connect` and `/profiles`); Enter on a size stores it and opens `/profiles` |

| `/profiles` | `ProfilePickerComponent` (`profile-picker/`) | "Who's watching?" start page; manage mode; PIN pad for locked profiles |
| `/profiles/new`, `/profiles/:id/edit` | `ProfileEditorComponent` (`profile-editor/`) | Name (on-screen keyboard), avatar, kids flag, PIN lock, delete |
| `/movies` (`data.media='movie'`) | `MoviesPageComponent` (`movies-page/`) | Section page: fills the catalog, enriches the focused item, hosts `<movie-description>` + child outlet |
| `/movies/list` | `MoviesSliderComponent` (`movies-slider/`) | Category rows of posters (+ the section's search bar, in `movies-page`) |
| `/releases/movies`, `/releases/shows` | `ReleasesPageComponent` (data `kind: 'movie'` / `'tv'`) | "Find releases" of a movie / show (`ReleasesService.open`); `ProfileGuard`. The paths contain `/movies` / `/shows` so the menu keeps that section highlighted |
| `/movies/movie/:id` | `MovieOptionsComponent` (`movie-options/`) | Movie detail: Play (or Resume) / Trailer / Find releases (→ `/releases/movies`, "title year") / Add to watch list / Mark as watched, cast row, similar row. `:id` = TMDB id |
| `/shows` (`data.media='tv'`) | `MoviesPageComponent` | Same as `/movies`, TV catalog |
| `/shows/list` | `MoviesSliderComponent` | TV rows |
| `/shows/show/:id` | `ShowOptionsComponent` (`show-options/`) | Show detail: Play / Trailer / Find releases (→ `/releases/shows`, show name + IMDb id for EZTV) / Add to watch list, seasons row (IMDb season mean on each chip), episodes row (IMDb rating per card, `<season-curve>` beside the title, watched badge / progress bar per episode). `:id` = TMDB TV id |
| `/shows/show/:id/season/:season/episode/:episode` | `EpisodePageComponent` (`episode-page/`) | One episode: title block (IMDb rating + votes, TMDB score, air date, runtime, "Best rated of season N", overview, director / writers), Play (or Resume) / Find releases (→ `/releases/shows` searched for "<show> SxxEyy") / Mark as watched, the season's episodes row, guest stars row |
| `/watchlist` | `WatchlistPageComponent` (`watchlist-page/`) | The profile's library: Continue watching, My list, Watched (history) |
| `/adult` | — (`AdultLayoutGuard` redirect) | Opens the profile's 18+ layout: `/adult/browse` (posters, default) or `/adult/releases` (compact). All `/adult/*` routes: `AdultGuard` (no profile → `/profiles`, kids → `/movies/list`) |
| `/adult/browse` | `AdultBrowseComponent` (`adult-browse/`) | 18+ poster layout: metadata provider rows (like the movies page), search, studio / release-period filters |
| `/adult/title/:provider/:id` | `AdultTitleComponent` (`adult-title/`) | One 18+ title: details, performers, Play (torrents by title + year), Find releases, More from <studio> |
| `/adult/releases` | `ReleasesPageComponent` (`releases-page/`, data `kind: 'adult'`) | 18+ compact layout: one torrent source's releases, most seeded first, search and filters |
| `/player/:session` | `PlayerPageComponent` (`player-page/`) | Plays its entry's `PlaybackRequest` (movie or episode); one `session` per playback (`PlaybackService.play`), so the next episode replaces the entry with a new component |
| `/search` | `SearchPageComponent` (`search-page/`) | On-screen keyboard, filter chips (All / Movies / TV shows / Anime / People), TMDB search with one row per result type |
| `/ytplayer/:id` | `YoutubeComponent` (`youtube/`) | Trailer player (server side currently broken, see root CLAUDE.md) |
| `/settings` | `SettingsPageComponent` (`settings-page/`) | This device's settings (for now: Display › Size); a section beside the menu, `ProfileGuard` |
| `/power` | `PowerPageComponent` (`power-page/`) | Quit / Sleep / Shutdown / Restart → the Electron shell (`window.playpex.power`) |

`movies`, `shows`, `watchlist`, `player`, `search`, `ytplayer` are guarded by `ProfileGuard` (no current profile → `/profiles`); the `/profiles*` routes by `ServerGuard` (no usable server → `/connect`), which covers the whole app. The current profile is in-memory only: every app start goes through "Who's watching?".

Reached from: start → (`/display` on the first start on a device) → (`/connect` when there is no server) → `/profiles` → Enter on a profile → `/movies/list`. Section pages (movies / TV lists, search, watch list, 18+) → Escape until the menu, then `/power` (search: straight to `/power`, it has no menu); Escape on `/power` → back to that section. Menu "Search" → `/search`, "Movies" → `/movies/list`, "Tv shows" → `/shows/list`, "Watch list" → `/watchlist`, "18+" → `/adult` → the profile's layout (item hidden for kids profiles). Poster Enter → the catalog's detail URL.

## Spatial navigation — how focus works (read before touching any page)

Library: `apps/tv/src/plugins/spacialNavigation.js` (vendored js-spatial-navigation; `init, add(config), remove(id), focus(id?), makeFocusable(id?), disable/enable, setDefaultSection`). Fires DOM events `sn:focused`, `sn:unfocused`, `sn:willmove`, …

Pages never call the library directly. They send instructions through `NavigationService`:

```ts
// on view init
this.navigation.updateNavigation('add', {
  id: 'showOptions',                              // section id (unique!)
  selector: '.showOptionsContainer .focusable',   // focusable elements (<button> or tabindex)
  restrict: 'self-only',                          // don't leave except via leaveFor
  leaveFor: { left: '@menu' },                    // '@<sectionId>' or a CSS selector
  enterTo: 'last-focused',
  straightOnly: true,
});
this.navigation.updateNavigation('focus', { sectionId: 'showOptions' });

// on destroy — ALWAYS remove sections you added, or ids collide next time
this.navigation.updateNavigation('remove', { sectionId: 'showOptions' });
```

Pages declare their sections in templates with `pxSection` and move inside them with the **movement system** (below). The player is on it too; it only takes the arrows that mean time itself (a `window` capture listener, before the library): see "Player".

Section ids in use: `menu`, `slider`, `options`, `showOptions`, `playerControls`, `subs`, `keyboard`, `searches`, `searchFilters`, `powerControls`, `okBtn`, `torrentPicker`, `profiles`, `profileEditor`, `textKeyboard`, `avatarChooser`, `confirmDelete`, `pinPad`, `library`, `sectionToolbar`, `releasesFilters`, `releasesList`, `adultToolbar`, `adultPosters`, `adultFilterPanel`, `adultTitle`, `episodePage`, `catalogFilters`, `serverPicker`, `pairing`, `connectionLost`, `displaySetup`, `settings`. Pages that show the left menu re-register `menu` with their own `leaveFor.right` (`FocusEngine.target([...])` for fallback chains / container targets). Migrated pages declare their own sections with `pxSection` (same ids).

Key handling (bindings live in `keymap.ts` — change keys there only):
- Arrows → library fires `sn:willmove` → `FocusEngine` moves inside movement containers, else the library moves focus → `sn:focused` → `AppComponent` adds `.focused` (style hook), `FocusEngine` remembers + scrolls, page listeners react (unmigrated pages scroll rows via `transform`; position memory, menu collapse…).
- `select` (Enter) → `NavigationService.addCommand('click')` (except on list-page posters → `AppComponent.moviesPageNavigation`, and on a menu item → `MenuServiceService 'navigate'`).
- `back` (Escape) → `addCommand('back')`.
- Every subscriber to `executeCommand()` checks `this.router.url`.
- Programmatic `element.focus()` only produces `sn:focused` when the window has OS focus (matters for headless/offscreen testing); `SpatialNavigation.focus(el)` (global `window.SpatialNavigation`) always does. Real keys work in an offscreen Electron window when sent with Electron's key names: `webContents.sendInputEvent({type:'keyDown', keyCode:'Right'})` (`Left/Up/Down`, `Return`, `Escape`), **not** `'ArrowRight'` (silently ignored).

## Movement system (`movement/`) — focus movement and native scrolling

Plan and rationale: [`docs/movement-system-plan.md`](../../docs/movement-system-plan.md). Every page uses it, the player included (2026-10-22). Translated (`transform`): the movies / TV rows, the watch list, the 18+ posters. Scrolling: `movies-page`'s `.pageContainer` (detail pages' rows), search, the 18+ title page and release list, the torrent picker, keyboards and panels.

Principles: movement **inside** a container is **by index**, geometry (the library) only between sections; focus drives scroll for keys, scroll never drives focus for the mouse; wiring is declarative in templates. **How** a container moves is its **motion** (`motion.ts`), chosen per container, everything else (engine, memory, paging, handoff) is shared:
- `motion="scroll"` (default): the container really scrolls (`overflow: auto`, hidden scrollbars), native wheel / trackpad / momentum, CSS snapping; glides are rAF tweens (`Scroller`). For detail pages, lists, panels.
- `motion="transform"`: the container clips, its track is moved with `translate3d` + a CSS transition (runs on the compositor: stays smooth while the page is busy). The browser can't scroll it, so `FocusEngine.wheel()` steps it: vertical wheel = one row of the stack, sideways (trackpad, tilt, shift + wheel) = one poster of the row under the cursor, focus unchanged. **For category pages** (cards in rows): 18+ posters, watch list, later the movies / TV rows.

| Piece | What it does |
|---|---|
| `pxItem` `[pxItemKey]` | Marks an item of a container; the key is what positions are remembered by. Must also be in a nav section (`pxSection` picks up `[data-px-item]` and `.focusable`). |
| `pxRow="key"` (`exportAs: 'pxRow'`) | Horizontal scroll container (adds `.px-scroll-x`). Left/right = index ± 1; `align` `start` (posters) / `third` (cast, episodes) / `nearest` / `center`; `[loadAhead]` / `[loadAheadPx]` → `(nearEnd)` on focus or scroll near the end; `page(±1)` (the `rowArrows` chevrons call it); `edges` (BehaviorSubject `{start, end}`: cut off on that side or not, from the real position, also on resize) + `atStart`/`atEnd` classes. |
| `motion="scroll"\|"transform"` (any container) | See above. Nested containers inherit their parent's (rows take their stack's). A transform stack needs a `pxTrack` child wrapping its rows (the host clips, things beside the track such as the `.overlay` stay put); a transform row is its own track and relies on an ancestor (its stack) to clip. Positions are offsets either way (`Motion.offset/viewport/moveTo/moveBy/toContent`), so containers never read `scrollLeft` themselves. |
| `pxStack="id"` | Vertical sequence of entries (rows, grids or single items; adds `.px-scroll-y`). Up/down = neighbour entry's remembered item, empty entries skipped. `align="row-top"` (adds room after the last row so it can reach the top) or `nearest`. `[snap]` (default on for `row-top` with scroll motion; transform stacks step by rows anyway): wheel / trackpad scrolling snaps to the entries' blocks (CSS `scroll-snap`, `.px-snap-y` / `.px-snap-point`; the Scroller adds `.px-snap-paused` while it glides). `pxStackItem` marks the block to align (a row's section with its title). |
| `pxGrid` | 2D / one-column list (chips, keyboards, the release list, short button lines). Sideways within a visual line, up/down to the nearest entry of the next line (`columns="auto"` reads lines from layout). Doesn't style overflow: the page decides whether it scrolls. |
| `pxSection="id"` | Spatial-nav section added on init, removed on destroy, re-added when `[leaveFor]` changes. Targets: `'@section'`, a CSS selector, `'stack:<id>'` / `'row:<id>'` / `'grid:<id>'` (entered at the remembered item) or an array tried in order. `[trap]="true"` = modal. Don't nest sections. |
| `enter="remembered"\|"nearest"` (any container) | Entering a container: its remembered entry (default) or the on-screen entry nearest to where focus comes from (keyboards, filter grids). |
| `FocusEngine` | Window listeners (`sn:willmove`, `sn:focused`, keydown, capture). Asks the innermost container for the next item, cancels the library's move when it has one; drops key repeats closer than a frame. `focus(el, cause)`: `key` (remember + glide), `pointer` (no scroll, not remembered), `select` (Enter/click: remember, no scroll), `restore` (instant). `restore('stack:<id>')` on page entry; `target([...])` builds a library `leaveFor` value (the library calls functions, a small Playpex patch). First arrow after the mouse scrolled: continues from the on-screen item nearest to the alignment point instead of jumping back. |
| `Scroller` | rAF tween per container and axis (easeOutCubic, 250 ms), re-targets a running tween (held keys glide), instant with `prefers-reduced-motion` / hidden windows, stops when the user wheels or drags. Pure alignment helpers (`alignedScroll`, `offsetWithin` — offsets, transforms ignored). |
| `PositionStore` | `<stack>/<row>` and `<id>` → `{key, index, scrollLeft, scrollTop}`, in root (survives the player / title pages), cleared on profile change. Pages `clear(id)` when their data is replaced (new search / filter). |

**Building a page** (see the movies slider, the watch list or the 18+ pages):
1. Template: `pxSection` on each focus area; rows → `pxStack` + `pxStackItem` + `pxRow` + `pxItem`; small button lines / chip grids / keypads → `pxGrid`; **every `pxRow` goes inside a `rowArrows` wrapper** (`<div class="slider" rowArrows><div pxRow=…>`; an existing wrapper of the row takes the attribute, else add a plain `<div rowArrows>`). A detail page under `movies-page` doesn't need a stack: its grids / rows become entries of `.pageContainer`'s.
2. Component: no scrolling code; a `sn:focused` listener only for **data** (description, backdrop, loading a season); paging from `(nearEnd)`; initial / return focus = `engine.restore('stack:<id>')` (falls back to the first on-screen item); register `menu` with `leaveFor.right: engine.target(['stack:<id>', '@<section>'])`; `positions.clear(id)` when the page's data is replaced.
3. SCSS: a scrolling container needs a definite size (`height`, or flex `min-height: 0`); rows need room for the focused item's zoom inside them (`padding` + negative `margin`, `scroll-padding-inline` = the padding; posters 180×270 ×1.1 → `16px 10px`, keeps the previous poster hidden) and the stack the same sideways room.
4. Verify with the checklist in the plan (§9).
- In a stack, revealing the **first** entry scrolls the stack back to its very start, so what's above it (a description, a search field) shows again.

Picking the motion for a new page: category rows of posters → `transform` on the stack (+ `pxTrack` on the rows' wrapper); anything else → leave the default.

## UI system (`ui/`, `../styles/`)

Plan and status: [`docs/ui-system-plan.md`](../../../../docs/ui-system-plan.md) (steps 0–1 done: tokens, units, screenshots; step 2, overlays, built and being verified, see its "Step 2 notes"; atoms, rows, layouts and slots come in steps 3–7).

- **Overlays** (`ui/overlay/`): `<px-dialog>` (modal: title, subtitle, a scrolling list of `<px-option>`s) and `<px-panel>` (full-screen: optional title, your own content and movement containers; `edge="end"` + `width`: docked at the right edge over a side gradient, the player's subtitles) are **open while they exist** (`*ngIf` on them): a nav layer (select / back are theirs), a trapping `pxSection` named `id`, first item (or `focus` selector) focused, focus restored on close. `level` = panel / modal / alert / system (priority + z). `(back)` listened to = Back is yours; else Back closes it and `(closed)` fires. ## Player (`player-page/`)

Redesigned on 2026-10-22 (`docs/ui-system-plan.md` §0 "Player"). Payload: a `PlaybackRequest`; route `player/:session`.

1. `ngOnInit`: read the payload (none → back). Resume state, subtitle size (`localStorage['playpex.subtitleSize']`), key listeners, stats polling, the next episode (episodes), the pointer. Development builds: `devSrc` plays a video file with no torrent (`window.playpexDev.player(src, 'movie' | 'episode')`).
2. `registerTorrent(magnet)` → keep `infoHash` → `getTorrent` → `repeat({delay: 4000})` until `files`; > 4 tries → `leavePlayer()` + error; an error answer (e.g. 503 `BUSY`) → `leavePlayer()` + the server's message. From the first answer on, `startKeepalive()` posts `keepTorrent` every 60 s (title, profile, file, position, paused) until destroy.
3. File: episodes → `pickEpisodeFile(files, s, e)` (`SxxEyy`, `s2e5`, `2x05`; inside season packs too; a lone video file is accepted); movies → `pickVideoFile` (mp4 > m4v > mkv > webm, then largest). None → error + `leavePlayer()`. `probeFile()`: Dolby / DTS audio → the server's `/transcode` stream (`position()` / `mediaDuration()` add its `offset`; seeks restart it on a keyframe, `seekTo`).
4. **View** (Angular state, no `style.display` toggling): loading view (title, the torrent's steps: starting → peers → torrent info → downloading the start, swarm numbers), controls (title block; the **timeline**: played amber, the downloaded range around the playhead light, the rest hatched; times, "Ends at …"; buttons: Subtitles · 10 s back · Play/Pause · 10 s ahead · Next episode (episodes) · Stats; icon-only, the focused one a white pill with its label), notices, Up next card, stats panel. Controls hide after 6 s without a key while playing (not while paused, scrubbing, in the subtitles panel or with the cursor shown).
5. **Input** (movement system): the controls are `pxSection="playerControls"` → `pxStack="player"` of the timeline (`.scrubber`, one `pxItem`) and the buttons (`pxGrid`, `(pxSelect)` each). `onKeyDown` (window capture, registered after the `FocusEngine`'s) takes only what means time, when no layer is open and playback is ready: controls hidden → ←/→ scrub, ↑/↓ show the controls (↑ on the timeline, ↓ on Play), OK = play the next episode while Up next shows, else pause/play + controls; controls shown → ←/→ on the timeline scrub, ↑ on it hides the controls. Everything else is the engine's.
6. **Scrubbing**: a press moves a preview mark (`scrub.target`) by 10 s, held (presses in a row) 30 s after 5, 1 min after 15; the tab shows the target and the delta, outlined when it lands outside the downloaded range ("not downloaded yet: it loads first"). The seek happens once, 350 ms after the arrow is let go (1.4 s without a key-up), or at once on OK; Back cancels it. One seek per run of presses (a transcoded stream restarts on each).
7. Back ladder (once playing): a scrub → Up next (controls hidden) → controls → stats → leave. Before playback is ready, Back leaves. The subtitles panel is a layer: it closes itself.
8. **Subtitles**: `px-panel id="subs" edge="end"` (a layer docked at the right edge; focus on the selected row, back on the Subtitles button when it closes): Source chips (providers enabled for this kind; the choice is remembered), the list (Off + the provider's results, a scrolling `pxGrid`), **Size** (Small / Medium / Large / Largest = `--px-text-heading / -headline / -title / -large`, through `--px-subtitle-size` on `video::cue`; per device), **Timing** (Earlier / Later by 0.5 s, Reset; this playback only). `applyCueShift()` moves the cues by the difference between what's applied and file time − the transcode offset + the delay.
9. **Up next** (episodes, not 18+): `EpisodePlaybackService.next()` finds the following aired episode from TMDB on init (the next of the season, else the first of the next one); its release (`bestTorrent()`: the server's ranking, the first that plays here) is looked up in the last 100 s. The card shows in the last 40 s (still, code + name, an amber countdown to the end); OK plays it, Back dismisses it, the end of the video plays it unless dismissed. `playNext()` → `EpisodePlaybackService.playNext()` → `PlaybackService.play(…, { replace: true })`: straight to that release (its saved position if any), the current entry replaced.
10. `leavePlayer()` = `navigator.back()`; the screen's `beforeLeave` releases the lease (`removeTorrent`). Resume / progress (`tmdbId`, not 18+, not `devSrc`): `startAt` if set, else `LibraryService.state()` → `applyResume()` on the first `canplay` (unless within 30 s of the end); `saveProgress()` every 15 s while playing, on pause, at the end, before Up next plays and in `ngOnDestroy`; never before the resume seek. `<video>` `error` → error + leave. 5 s of video with no decoded audio → the "No sound" notice. The shell's clock fades while actually watching (`updateClock`).

## Recipes

**Add a new page/route**
1. `ng g c my-page` (adds to `AppModule.declarations`), add the route in `app-routing.module.ts`.
2. Template: `pxSection` (+ movement containers, see "Movement system"); in `ngAfterViewInit`: focus something; subscribe to `navigation.executeCommand()` guarded by `this.router.url`.
3. Handle `'back'` and `'leave'` (usually `navigation.goBack()`; `leave` must leave the page, not just move focus), `menuService.sendInstruction('hide'|'show'|'collapse')` as needed.
4. In `ngOnDestroy`: remove sections you added in code (the `menu` re-registration), unsubscribe, remove window/document listeners.
5. Menu entry: `<button class="tabGroup element menuItem" data-destination="x">` in `menu.component.html` + a case in `MenuComponent.navigate()`.
6. If the component's host is a flex item of `.pageContainer`/`.masterContainer` and contains wide rows, give it `:host { display: block; min-width: 0; }`.

**Add a row**: append `new Category(name, {url, params: {}})` to `categories` or `showCategories` (use `<<api_key>>`). Paging and slider wiring are automatic.

**Add another section (e.g. anime)**: add a `MediaType`, a `Catalog` in `MoviesService.catalogs`, routes with `data.media`, an enrichment branch in `MoviesPageComponent`, and a detail component.

**Call a new server endpoint**: describe it in `packages/protocol/openapi.yaml` first (see `apps/server/CLAUDE.md`), then add a method in the relevant service using `` `${this.server.api}/…` `` (inject `ServerService`); type the answer with `Schema<'…'>` from `@playpex/protocol`.

**Don't name an element `.description`** (or `.menuItem`, `.element`, `.tabs`) outside the menu: `MenuComponent` queries those document-wide (e.g. collapsing sets `display:none` on every `.description`). Menu items rendered after a collapse (the profile entry) rely on the `.menuContainer:not(.expended) .description { display: none }` rule.

**Mouse**: hover/click/back work automatically for anything in a spatial-nav section; wheel scrolling (native, or stepped for translated containers) and correct hover come with the movement containers. Mouse-only controls are plain `(click)` elements that no section's selector matches (no `.focusable` / `pxItem`); show them only under `body:not(.pointer-hidden)` (the row chevrons: `rowArrows`). Decorative layers over content need `pointer-events: none` (all `.overlay` elements have it globally).

**Rows next to the menu** (movies / TV, watch list, 18+ posters): the stack clips (posters moved off to the left must not show over the menu); 10px of sideways padding on it and on the rows (with matching negative margins) is room for the focused poster's 9px zoom and keeps the previous poster (10px gap) hidden.

**Styling**: per-component SCSS built from the UI system's tokens (see "UI system" below); global fonts and the root size in `apps/tv/src/styles.scss`. Focus state is the `.focused` class (outline disabled globally). Designed on 1440 × 810, scales with the window: lengths in `dp(n)`, never px.
