# Playpex for phones — plan

**Status (2026-10-27):** proposed and started. Step 1 (the app, connecting, pairing, profiles) and step 2 (browsing, a title's page)
built; step 3 (Play: sources, the player, leases, progress) built, not yet tried on a phone; step 4 (the player's features, as the
TV's player: Audio & subtitles with a torrent's separate files, online subtitles, subtitle style and timing, audio sync, speed,
picture, brightness, a torrent's other videos, stats, Skip intro, Up next; the TV's layout) built 2026-10-30, not yet tried on a
phone; steps 5–8 open.

Playpex Mobile (`apps/mobile`, `@playpex/mobile`) is the second client of Playpex Media Server, after Playpex TV: a phone app
(Android first, iOS from the same code later) that finds a server on the Wi-Fi, pairs with it like any client
([`docs/api/`](api/README.md)), and browses, plays and resumes what the server has and finds. It follows the client author
guide and nothing else: no route of its own on the server, no admin feature (that is the Server Manager, `apps/manager`, which
opens the dashboard; it stays a separate app).

Playpex is an educational project; streaming copyrighted content via torrents may be illegal where you live.

## 1. Decisions

| | Decision | Why |
|---|---|---|
| A | **React Native with Expo** (SDK 58, development builds, Continuous Native Generation: `android/` and `ios/` are generated by `expo prebuild`, never edited) | native players and touch UI; TypeScript like the dashboard; the protocol's generated types and `openapi-fetch` reused as is |
| B | **libmpv on the phone** (`modules/expo-mpv`: [expo-mpv](https://github.com/lonzzi/expo-mpv) 0.1.21 vendored, GPL-3.0; mpv-android's libraries on Android, MPVKit on iOS), hardware decoding first (MediaCodec / VideoToolbox), FFmpeg in software for the rest. Revised 2026-10-27: first `react-native-video` (ExoPlayer / AVPlayer) | **maximum compatibility, all native**: every container (MKV, MP4, AVI, TS, WMV…), video (H.264, HEVC, AV1, VP9, MPEG-2, MPEG-4 / XviD, VC-1), sound (Dolby Digital, Dolby Digital Plus, TrueHD, DTS, DTS-HD, FLAC…) and subtitle (SRT, styled ASS, PGS / VobSub images) decoded on the phone, the file's tracks switched natively. ExoPlayer only has the phone's hardware decoders (`react-native-video` turns its FFmpeg extension off: no DTS / TrueHD on most phones), AVPlayer opens no MKV. One engine on both platforms. Playpex adds an `httpHeaders` prop (mpv's `http-header-fields`: the token reaches HLS segments and subtitle files too) |
| C | **Files play as they are** (`GET /media/{ref}` directly, no `/playback` decision, no server transcoding); `PUT /devices/me` declares every codec (`PLAYER_CAPABILITIES`) with the hardware's `maxHeight` (`MediaCodecList`) | the phone decodes everything (B), so nothing is converted and the server's ffmpeg stays free; asking `/playback` would only make the server probe the file (seconds on a torrent still downloading) |
| D | **Discovery and codecs in a local Expo module** (`modules/playpex-device`, Kotlin): mDNS (`NsdManager`) + the UDP broadcast, every address confirmed with `GET /server`, ported from the Server Manager's `PlaypexDiscovery.java`; `codecs()` | React Native has no UDP broadcast or NSD of its own; one module, no third-party native code |
| E | **Tokens in the platform's secret storage** (`expo-secure-store`: Android Keystore, iOS Keychain), servers stored by `id` | [auth](api/auth.md#storing-tokens) |
| F | **Navigation with Expo Router** (files under `src/app/`); state with TanStack Query (as the dashboard) and one session context (server, API client, profile) | no NgRx-like store; query caching gives the catalog's 1 h / 6 h for free |
| G | **The token in the `Authorization` header**, never in URLs: mpv sends the session's headers with every request of a file (the stream, HLS segments, subtitle files it adds) | [auth](api/auth.md#making-requests) |
| H | **The TV's look on a phone**: its near-black ground, white for what is chosen, amber for progress (`src/ui/theme.ts` mirrors `apps/tv/src/styles/_tokens.scss`'s palette) | one product |
| I | Portrait for browsing, landscape full screen for the player | phones |

## 2. Steps

1. **The app** — Expo workspace, `app.json` (cleartext HTTP to LAN servers, local network on iOS: `NSBonjourServices` `_playpex._tcp`,
   `NSLocalNetworkUsageDescription`), the native module, **Connect** (servers found, "Enter an address", the last one at start,
   re-found by `id` when its address changed), **Pair** (RFC 8628: the code in two halves, the server's `/link` address, "Open on
   this phone" for an admin who is on it, polling with `slow_down` / `expired_token` / `access_denied`, then `PUT /devices/me`),
   **Who's watching?** with PINs. `401 PAIRING_REQUIRED` → forget the token, back to Connect with the reason; `426` → which one to update.
2. **Browsing** — tabs Home (continue watching, then rows from `/catalog/lists/*`), Movies, Shows, Search (`/catalog/search/multi`),
   My list (`/profiles/{id}/library`); a title's page (backdrop, meta line, IMDb rating, watch list, seasons and episodes with
   progress bars, cast).
3. **Play** — `POST /play/sources` → `policy.autoplay`, else the chooser grouped by kind (On this server / Stream / Torrent, the best
   first); `POST /play/start` (ask / refuse); a torrent: `POST /torrents`, poll with `season` / `episode` / the file hint for
   `chosen`, "Connecting to peers" from `/stats`; the file as it is (libmpv); the player: keepalive every 60 s, progress every
   15 s and on pause / exit, `DELETE` on leaving, resume ("Resume from 20:01"), Up next for episodes.
4. **Tracks and subtitles** — the file's own tracks are switched by mpv already (step 3); then a torrent's other files from
   `GET /media/{ref}/tracks` (separate audio / subtitle files: mpv's `audio-add` / `sub-add` on their `/media/{ref}`), subtitle
   providers' files (`/subtitles/file`, `sub-add`), subtitle size and timing (`sub-delay`), the chosen tracks saved with the progress
   and the profile's `player.*` settings.
5. **Library and downloads** — "On this server" marks (`/library/titles/*`), the Library tab (`/library/home`, folders), a "Download"
   button (`POST /downloads` with `media`), live with the events WebSocket (`download.*`, `library.changed`).
6. **Plugins** — what clients render (`GET /plugins`: the `catalog` / `title` / `releases` / `list` / `guide` templates, slots,
   effects), live TV (`/live/*`, the player's channel mode), "Skip intro" (`/play/markers`).
7. **Phone things** — picture in picture, background audio and the media notification, Cast (`react-native-google-cast`: the
   server's URL + token to the receiver), resume on another device ("Continue on TV" later).
8. **iOS and releases** — local network permission, the discovery module's iOS side (Bonjour + UDP), MPVKit (iOS 16.4+), signing,
   EAS or local builds, an update channel.

## 3. Out of scope

Admin features (pairing approvals, settings, plugins' setup: the dashboard and the Server Manager), downloads to the phone
(offline viewing: maybe later, through `/downloads` files and the system download manager), Android TV (Playpex TV covers TVs).
